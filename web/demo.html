Hawk Post-Quantum Signatures

Hawk is a lattice-based digital signature scheme built on the Module Lattice Isomorphism Problem (Module-LIP). It reached Round 3 of NIST's Additional Signatures process as the only remaining lattice-based candidate, then was withdrawn in July 2026 after a practical key-recovery attack. Everything below describes the scheme as specified in Hawk v1.1 — it is a study of a broken design, not a usable one.

Protocol Overview
1
Key Generation
Generates a short NTRU lattice basis (f, g, F, G) from a random seed. The public key encodes q₀₀ = ff* + gg* and q₀₁ = Ff* + Gg* in the ring ℤ[x]/(xⁿ+1). The private key stores a compressed seed plus F mod 2, G mod 2.
2
Signing
Hashes the message to get polynomials (h₀, h₁) using SHAKE-256. Samples a short vector (s₀, s₁) from a discrete Gaussian centered at the lattice coset. Outputs (salt, s₁) — the salt and the second signature polynomial.
3
Verification
Reconstructs s₀ from s₁ and the public key, recomputes the hash, checks the sym-break condition and that the norm ‖(s₀, s₁)‖_Q² ≤ 8n · σ_verify² holds. Returns True iff all checks pass.

About Hawk

Hawk is a post-quantum digital signature scheme by Léo Ducas, Eamonn Postlethwaite, Ludo Pulles, and Wessel van Woerden, based on the Module Lattice Isomorphism Problem.

Security Foundation

Hawk's security rested on the hardness of the Module Lattice Isomorphism Problem (Module-LIP) in the ring ℤ[x]/(xⁿ+1) — distinct from the LWE/SIS assumptions behind ML-DSA and Falcon. That assumption did not hold for Hawk's power-of-two cyclotomics: the 2026 attack uses the Galois involution ζ ↦ −ζ to halve the lattice dimension an attacker must reduce.

Hash-Then-Sign Design

Hawk uses a hash-then-sign approach: the message is first hashed to a lattice target vector (h₀, h₁) using SHAKE-256, then a short preimage is found by sampling a discrete Gaussian distribution over the lattice coset.

Key Structure

The private key is a short NTRU basis (f, g, F, G) satisfying fG − gF = 1 mod q. The public key encodes the Gram matrix polynomials q₀₀ and q₀₁ derived from this basis. Key generation uses NTRUSolve from Falcon.

Compact Signatures

Hawk-512 signatures are 555 bytes, smaller than Falcon-512 (666 bytes) and dramatically smaller than SPHINCS+, with no floating-point arithmetic anywhere. This compactness was the scheme's main appeal — and restoring security would have required doubling parameters, which is exactly why the team withdrew it rather than repairing it.

NIST Process

Hawk advanced to Round 3 of NIST's Additional Digital Signatures call in May 2026 as its only lattice-based candidate, then was withdrawn on 29 July 2026. Its claimed levels — Hawk-512 at NIST level I, Hawk-1024 at level V — no longer hold: key recovery drops from 2150 to 2108 and 2288 to 2182 gates respectively.

Implementation

This demo uses hawk-sign/hawk-py — the Python specification implementation. The reference C implementation (ref + AVX2) is in hawk-sign/dev with 10–100× better performance.
